# nashville.com → Nashroam redirect layer

Legacy nashville.com URLs are mapped to Nashroam pages so backlink equity survives the
domain move. Nothing is hard-coded: the rules come from the backlink audit workbook and
are regenerated by a script. The layer is scoped to the `nashville.com` hosts, so it is
**inert until DNS points nashville.com (and www, and tickets) at this Vercel project**.
nashroam.com traffic is never touched.

## Files

| Path | What it is | Edit by hand? |
| --- | --- | --- |
| `data/migration/nashville_com_backlink_audit_redirect_map.xlsx` | Backlink audit export (Semrush) with the redirect decisions. **Not in the repo yet; drop it here.** | Yes, this is the source of truth |
| `data/migration/redirects.json` | Generated rule list: `{ source, destination, status: 301 \| 410, referringDomains, note }` plus the hosts it applies to and the absolute `target` origin | No, regenerate |
| `data/migration/priority-restores.json` | Generated list of mapped URLs with ≥100 referring domains, for the "republish as a real article" decision | No, regenerate |
| `data/migration/nashroam-routes.json` | Generated inventory of every route Nashroam serves (static pages plus published slugs) | No, regenerate |
| `scripts/build-redirects.ts` | Workbook → JSON builder | Only to change parsing |
| `scripts/lib/migration.ts` | Parser, path normalisation, route inventory | Only to change parsing |
| `next.config.mjs` `redirects()` | Reads `redirects.json` and emits exact-match 301s (both trailing-slash forms, host-scoped) | Never inline rules here |
| `src/middleware.ts` | Wildcards, host rule, 410s, mixed-case and `/?p=` sources | Only to change wildcard behaviour |
| `tests/redirects.test.ts` | Fails the build if a destination is not a Nashroam page | Add cases as needed |
| `docs/migration/REDIRECTS.md` | This checklist | Yes |

## What is handled where

Exact-match 301s live in Next's `redirects()` because Next evaluates them before
middleware and they are the cheapest path. Everything `redirects()` cannot express is in
middleware, in this order:

1. `tickets.nashville.com/*` → `/events/` (host rule, 301).
2. Query-addressed sources from the map (`/?p=123`) and mixed-case requests (`/Hotels/`)
   → the mapped destination or 410.
3. `/~user/*`, `/wp-content/*`, `/wp-includes/*`, `/wp-json/*`, `/feed` and `*/feed` → 410,
   unless the map says otherwise.
4. `/?p=`, `/?page_id=`, `/?attachment_id=` with no rule → 410.
5. `/event`, `/event/*`, `/events/*` that is neither a Nashroam route nor in the map → `/events/` (301).

Every 301 preserves the incoming query string (for `/?p=123` rules the addressing key is
dropped, the rest is kept). Sources are matched case-insensitively and with or without the
trailing slash. Destinations are trailing-slash paths because `next.config.mjs` sets
`trailingSlash: true`, and they are emitted as absolute `https://nashroam.com/...` URLs:
once nashville.com resolves to this project, a relative destination would stay on the
nashville.com host and re-enter the layer forever. A slash-less request such as
`/hotels` takes two hops (Next's own trailing-slash redirect first, then the mapped 301);
that is expected and harmless.

## Workbook format

The builder finds the header row (it may sit under a title line) and recognises these
columns by name, case-insensitively:

| Field | Accepted headers |
| --- | --- |
| Source (required) | Source, Source URL, Old URL, Legacy URL, URL, Page URL, Target URL, Address |
| Destination | Destination, Destination URL, Redirect To, New URL, Nashroam URL, To, Maps To |
| Status | Status, Status Code, Action, HTTP Status, Code, Decision (`301`/`redirect`/`keep` or `410`/`gone`/`remove`) |
| Referring domains | Referring Domains, Ref. Domains, RefDomains, Linking Domains |
| Note | Note, Notes, Reason, Comment, Section, Category |

Rules of thumb the parser applies:

- A row with no destination, or a status that says gone, becomes a 410.
- The homepage row is skipped: equity transfers with the domain.
- Duplicate sources keep the first row; the rest are reported as skipped.
- Destinations may be full nashroam.com URLs or paths; both normalise to a path.
- Sheets named Summary, Readme, Notes or Legend are ignored. Pass `--sheet "Name"` to force one.

## Regenerate the map

```bash
# 1. Fresh data: export Semrush Backlink Audit → Indexed Pages (or the audit workbook
#    itself) and drop it at data/migration/nashville_com_backlink_audit_redirect_map.xlsx.
#    A Screaming Frog crawl of nashville.com (list mode, from the same URL set) is the
#    cross-check that the source URLs still resolve and that nothing was missed.

# 2. Build the JSON. Prints the sheet, headers, counts, unmapped destinations and section gaps.
npm run redirects:build
#    Options: --workbook path.xlsx   --sheet "Priority URLs"   --dry-run
#    MIGRATION_TARGET_ORIGIN=https://preview.example npm run redirects:build  (test builds only)

# 3. Guard. This is also the prebuild step, so `npm run build` fails on a bad map.
npm run test:redirects

# 4. Commit the regenerated JSON files with the workbook.
```

The build test fails when a 301 destination is not a page Nashroam serves today. Do not
create stub pages to satisfy it; remap the row to the nearest real page, or mark it 410.

## Missing sections (flag, do not scaffold)

nashville.com had sections Nashroam does not (yet) mirror one to one. The builder prints
the gaps on every run. Current mapping:

| nashville.com section | Nashroam | Decision |
| --- | --- | --- |
| `/hotels/…` | `/hotels/` and `/hotels/<slug>/` | Section exists; individual hotel URLs need a slug match or the hub |
| `/golf/…` | none | 410, or remap to `/things-to-do/` if the row has real equity |
| `/attractions/…` | `/things-to-do/` | Hub redirect unless a matching thing-to-do slug exists |
| `/music/…` | `/music/` and `/music/<slug>/` | Section exists |
| `/events/…` | `/events/` | Hub redirect for unknown legacy events (middleware wildcard) |
| `/articles/…` | `/guides/` | Hub redirect unless a guide covers the topic |

## Priority restores

`data/migration/priority-restores.json` lists every mapped URL with ≥100 referring
domains (for example `shinedown-to-make-grand-ole-opry-debut/`, 219 domains). Each entry
carries the current decision (301 target or 410) and a `decision` field left as
"undecided". These are the pages worth republishing as real articles at their old path so
the links resolve to content instead of a hub. That is a content follow-up, not part of
the redirect layer; leave the redirect in place until the article ships, then delete the
row from the workbook and regenerate.

## Cutover checklist

Before DNS:

- [ ] Workbook in place, `npm run redirects:build` clean (no unmapped destinations).
- [ ] `npm run build` green (the prebuild test passes).
- [ ] Priority-restore decisions recorded, at least for the top 10 by referring domains.
- [ ] Preview deployment tested with a spoofed host (see below).

Local or preview verification with a spoofed host (the layer keys off the `Host` header):

```bash
BASE=http://localhost:3000   # or the preview URL
curl -sI -H "Host: nashville.com" "$BASE/hotels/"                 # 301 → https://nashroam.com/hotels/
curl -sI -H "Host: www.nashville.com" "$BASE/Hotels?utm_source=x" # 301, query preserved
curl -sI -H "Host: nashville.com" "$BASE/~oldpage/"               # 410
curl -sI -H "Host: nashville.com" "$BASE/wp-content/uploads/a.jpg" # 410
curl -sI -H "Host: nashville.com" "$BASE/?p=123"                  # 410 (unless mapped)
curl -sI -H "Host: nashville.com" "$BASE/event/anything/"         # 301 → https://nashroam.com/events/
curl -sI -H "Host: nashville.com" "$BASE/events/this-weekend/"    # 200, Nashroam route passes through
curl -sI -H "Host: tickets.nashville.com" "$BASE/some/ticket/"    # 301 → https://nashroam.com/events/
curl -sI -H "Host: nashroam.com" "$BASE/~oldpage/"                # 404, layer inert on nashroam.com
```

Bulk status-code verification: put every source URL from the workbook (plus the wildcard
samples above) in a list, run Screaming Frog in list mode against the preview host with a
custom `Host` header, or the equivalent curl loop, and confirm that every row returns the
expected status and that no 301 lands on a 404. Run the same list again 24 hours after DNS.

DNS and Vercel:

- [ ] Add `nashville.com`, `www.nashville.com` and `tickets.nashville.com` as domains on the
      Vercel project (no redirect-to-primary setting; the app must see the original host).
- [ ] Point A/CNAME records at Vercel; wait for certificates.
- [ ] Re-run the curl checks against the live hosts.
- [ ] Google Search Console: verify nashville.com, submit the change of address to
      nashroam.com, keep both properties for 180 days.
- [ ] Watch Vercel logs for 404s on nashville.com hosts for the first two weeks; add rows
      to the workbook for anything with real traffic, regenerate, redeploy.

## Notes

- `redirects()` cannot return 410, and Next's matcher is case-sensitive; that is why the
  middleware exists. It short-circuits on host, so nashroam.com requests pay one string compare.
- The middleware matcher skips `_next/`, `api/`, `media/`, `brand/`, `fonts/` and the root
  static files; legacy asset URLs under those prefixes would not have existed on nashville.com.
- Static inventory excludes sample fixtures (`sample-*` slugs) and admin/api routes.
